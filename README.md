# 🚕 تاکسی خانم پاپلی — نسخه‌ی گیت‌هابی

این نسخه از برنامه طوری تغییر کرده که به‌جای سرور PHP و دیتابیس MySQL، از **گیت‌هاب** به‌عنوان محل ذخیره‌ی اطلاعات استفاده می‌کند و کاملاً روی **GitHub Pages** (رایگان) قابل اجراست. برای تک‌کاربر بودن برنامه مناسب است.

## این نسخه چطور کار می‌کند؟

- گیت‌هاب فقط فایل‌های ثابت (HTML/CSS/JS) را سرو می‌کند و نمی‌تواند PHP اجرا کند یا مستقیم به MySQL وصل شود؛ به همین دلیل تمام منطقی که قبلاً در `api/*.php` بود، الان با جاوااسکریپت در مرورگر خودتان (فایل `assets/gh-storage.js`) اجرا می‌شود.
- تمام اطلاعات (مشتریان، کرایه‌ها، بدهی‌ها، فاکتورها، رمز عبور) در یک فایل JSON به اسم `data/db.json` نگه‌داری می‌شود که هر بار با هر عملیات (ثبت مشتری، ثبت کرایه، پرداخت و ...) از طریق **GitHub API** خوانده و دوباره نوشته می‌شود.
- برای این کار به شما یک **Personal Access Token** گیت‌هاب نیاز است که فقط داخل مرورگر خودتان (localStorage) ذخیره می‌شود.

## ⚠️ نکته‌ی امنیتی مهم (حتماً بخوانید)

GitHub Pages رایگان فقط از **ریپوی پابلیک** سرو می‌شود؛ یعنی اگر کد سایت و فایل داده در یک ریپو باشند، اسم/شماره تلفن/بدهی مشتریانتان برای همه قابل مشاهده خواهد بود. برای همین در `setup.html` می‌توانید **ریپوی داده را جدا از ریپوی سایت** تعریف کنید:

- **ریپوی سایت**: پابلیک، همین است که روی GitHub Pages پابلیش می‌کنید (فقط شامل کد است، نه اطلاعات مشتری).
- **ریپوی داده**: یک ریپوی **Private** جداگانه بسازید (مثلاً `papoli-data`)؛ توکن دسترسی به آن، اطلاعات را می‌خواند/می‌نویسد، بدون این‌که این ریپو نیازی به Pages داشته باشد. توکن با دسترسی محدود (فقط همان ریپو، فقط Contents) امن‌تر است.

اگر ترجیح می‌دهید سادگی را فدای حریم خصوصی نکنید، همان یک ریپوی Private را هم برای سایت و هم برای داده استفاده کنید، اما در این حالت باید GitHub Pro (یا بالاتر) بگیرید تا Pages از ریپوی Private هم کار کند؛ در پلن رایگان فقط ریپوی پابلیک روی Pages منتشر می‌شود.

## مراحل راه‌اندازی

1. **ریپوی سایت را بسازید و کد را آپلود کنید**
   - یک ریپوی جدید (پابلیک) در گیت‌هاب بسازید، مثلاً `taxi-papoli`.
   - همه‌ی فایل‌های همین پروژه (به‌جز پوشه‌ی `legacy-php-backend`) را در آن push کنید.
   - در تنظیمات ریپو، بخش **Settings → Pages** را باز کنید و Source را روی شاخه‌ی `main` (پوشه‌ی root) بگذارید. بعد از چند دقیقه آدرسی شبیه `https://USERNAME.github.io/taxi-papoli/` فعال می‌شود.

2. **ریپوی داده را بسازید (Private)**
   - یک ریپوی دیگر با نام دلخواه بسازید (مثلاً `papoli-data`) و آن را **Private** کنید.
   - لازم نیست فایلی داخلش بگذارید؛ برنامه خودش هنگام اولین اجرا فایل `data/db.json` را می‌سازد.

3. **توکن دسترسی (Personal Access Token) بسازید**
   - به آدرس `https://github.com/settings/tokens` بروید → «Fine-grained tokens» → «Generate new token».
   - در «Repository access» فقط همان ریپوی داده (`papoli-data`) را انتخاب کنید.
   - در «Permissions» گزینه‌ی **Contents** را روی **Read and write** بگذارید.
   - توکن را بسازید و کپی کنید (فقط یک بار نشان داده می‌شود).

4. **اولین اجرای برنامه**
   - آدرس GitHub Pages سایت را باز کنید؛ چون هنوز تنظیم نشده، خودکار به `setup.html` می‌روید.
   - نام کاربری گیت‌هاب، نام ریپوی داده، شاخه (پیش‌فرض `main`) و توکن را وارد کنید و «ذخیره و اتصال» را بزنید.
   - بعد از تایید اتصال، به صفحه‌ی ورود منتقل می‌شوید. **رمز پیش‌فرض `1335`** است (از تب تنظیمات داخل برنامه قابل تغییر است).

## نصب روی گوشی

### روش ۱: نصب مستقیم از مرورگر (PWA) — پیشنهاد اصلی
این پروژه یک اپ وب قابل‌نصب (PWA) است:
- در گوشی اندروید (کروم): آدرس سایت را باز کنید → منوی سه‌نقطه → «Add to Home screen» / «نصب برنامه».
- در آیفون (سافاری): دکمه‌ی Share را بزنید → «Add to Home Screen».
بعد از نصب، آیکون برنامه روی صفحه‌ی اصلی گوشی می‌آید و مثل یک اپ مستقل باز می‌شود (بدون نوار آدرس مرورگر).

### روش ۲: فایل نصبی APK
ساخت واقعی فایل APK نیاز به Android SDK و کامپایل دارد که در این محیط در دسترس نیست، ولی می‌توانید با یک ابزار رایگان و رسمی به اسم **PWABuilder** (ساخته‌ی مایکروسافت) به‌راحتی از همین سایت یک APK بسازید:
1. بعد از فعال شدن GitHub Pages، به آدرس `https://www.pwabuilder.com` بروید.
2. آدرس سایت خودتان (لینک GitHub Pages) را وارد کنید و «Start» را بزنید.
3. در تب Android، گزینه‌ی ساخت پکیج را بزنید تا فایل APK دانلود شود.
4. فایل APK را روی گوشی اندروید منتقل و نصب کنید (باید نصب از منابع ناشناس را برای همان فایل اجازه بدهید).

## محدودیت‌های این روش (صادقانه بگویم)

- **تک‌کاربره**: این طراحی برای یک نفر با یک توکن است. اگر همزمان از دو گوشی/مرورگر وارد شوید و هر دو تغییری بدهند، ممکن است آخرین ذخیره، تغییرات دیگری را بازنویسی کند.
- **سرعت**: هر عملیات (ثبت کرایه، پرداخت و ...) یک درخواست به GitHub API می‌زند؛ نسبت به دیتابیس واقعی کمی کندتر است ولی برای استفاده‌ی روزمره‌ی یک راننده/دفتر کوچک کاملاً کافی است.
- **محدودیت نرخ درخواست گیت‌هاب**: برای توکن‌های شخصی معمولاً ساعتی چند هزار درخواست مجاز است؛ در استفاده‌ی عادی به آن نمی‌رسید.
- **نیاز به اینترنت**: چون داده روی گیت‌هاب است، بدون اینترنت نمی‌توانید اطلاعات جدید ثبت یا مشاهده کنید (فقط پوسته‌ی برنامه به‌خاطر PWA کش می‌شود).

## پوشه‌ی legacy-php-backend

فایل‌های اصلی PHP/MySQL (که این نسخه دیگر به آن‌ها نیاز ندارد) برای مرجع در پوشه‌ی `legacy-php-backend/` نگه داشته شده‌اند، شامل `data.sql` (ساختار دیتابیس اصلی) و پوشه‌ی `api/`. اگر بعداً خواستید به یک هاست واقعی PHP+MySQL برگردید، همین فایل‌ها را می‌توانید استفاده کنید؛ برای اجرای گیت‌هابی نیازی به آپلود این پوشه ندارید.
